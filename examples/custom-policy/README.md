# Custom policy

This example defines a policy from scratch, compiles it into a sleeve variant,
and composes that sleeve with the repository's existing HTTP scenario plugin.
The policy counts calls by WIT interface and refuses the fourth `send`.

The example owns three short pieces of source:

1. [`guest/policy/src/lib.rs`](guest/policy/src/lib.rs) implements
   `sleeve_core::Policy`. Its `before` hook increments an interface counter and
   returns a typed HTTP refusal on the fourth send. Its invocation-end observer
   writes the summary through an abstract `SummaryLog`.
2. [`guest/sleeve/src/lib.rs`](guest/sleeve/src/lib.rs) supplies that log using
   `sleeve:platform/audit`, builds `CountCalls` into a `Chain`, and asks the
   standard HTTP sleeve core to export the wrapper.
3. [`src/main.rs`](src/main.rs) starts a loopback server, pins the example's
   sleeve, and passes both sleeve and plugin bytes to `sleeve-host` for verified
   load-time composition.

Run it from the repository root:

```console
cargo run -p custom-policy
```

The first three requests reach the server, the fourth returns a typed denial,
and the policy prints its counts:

```text
plugin: 200, 200, 200, request denied
summary wasi:http/client@0.3.0 calls=4
summary wasi:http/types@0.3.0 calls=27
```

Run `support/count-wrapper-lines.sh` to reproduce the policy, sleeve, and host
source line counts reported with the other wrapper measurements. These three
files total 135 lines, including comments and binding declarations but not the
bindings generated by `wit-bindgen`.
